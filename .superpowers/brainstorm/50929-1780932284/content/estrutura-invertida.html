Serviço → Cliente → Subpastas

A lógica invertida. Dois caminhos para implementar isso — selecione o que faz mais sentido.

A

Raiz por serviço, mês dentro do cliente

Cada tipo de trabalho é uma pasta raiz. Dentro dela, os clientes. Dentro de cada cliente, o mês (para gestão de redes) ou direto o index (para identidade visual).

Estrutura de pastas
identidade-visual/

    index.html
  studioalma/
    index.html
 
gestao-de-redes-sociais/
  studioalma/
    junho-2025/
      index.html
    julho-2025/
      index.html

Identidade: lab360-entregas.vercel.app/identidade-visual/studioalma/
Calendário: lab360-entregas.vercel.app/gestao-de-redes-sociais/studioalma/junho-2025/

Prós

  • URL curta e direta
  • Histórico mensal por cliente
  • Fácil de expandir para novos serviços

Contras

  • Quebra a estrutura atual de clientes/ — precisa migrar
B

Híbrido — mantém clientes/ mas organiza por serviço dentro

Preserva clientes/ como raiz, mas dentro de cada cliente os serviços viram categorias com subpastas. Migração zero.

Estrutura de pastas
clientes/
  studioalma/
    identidade-visual/
      index.html
    gestao-de-redes-sociais/
      junho-2025/
        index.html
      julho-2025/
        index.html

Identidade: lab360-entregas.vercel.app/clientes/studioalma/identidade-visual/
Calendário: lab360-entregas.vercel.app/clientes/studioalma/gestao-de-redes-sociais/junho-2025/

Prós

  • Zero migração — existente continua igual
  • Lógica clara de serviço dentro do cliente

Contras

  • URL mais longa
  • Serviço ainda vem depois do cliente, não antes

Nota sobre migração

A opção A quebra a estrutura atual — o único cliente existente (quikciadadanca/moverconsciente) precisaria ser movido para identidade-visual/quikciadadanca/. São poucos arquivos, dá pra fazer sem dor.
